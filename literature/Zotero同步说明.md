# Zotero 与论文仓库同步说明

## 1. 管理边界

采用“双库分工”，不要让 Zotero 和仓库同时承担全部功能：

| 内容 | 唯一主库 | 说明 |
| --- | --- | --- |
| 文献元数据、PDF/CAJ、网页快照、Zotero 批注 | Zotero | 负责检索结果保存、附件、去重、批注和引文生成 |
| 文献编号 `LIT-xxxx` | `literature/文献总表.md` | 编号稳定，不随 Zotero 引用键变化 |
| 摘录与论文小节、段落的对应关系 | 仓库中的文献卡片 | 记录页码、准确转述、拟插入位置和证据状态 |
| 各章还缺什么文献 | `literature/章节文献地图.md` | 从论文写作任务反查证据缺口 |
| BibTeX/RIS 交换文件 | `literature/91-引用与导出/` | 从 Zotero 导出，供论文工具或核验脚本使用 |

严格来说，Zotero 的“分类”是集合，不是 Windows 物理文件夹。一个条目可以同时进入多个集合，跨章节不重复条目或附件。按用户明确要求，每篇原文在对应大纲目录保留一份本地副本，同时复制导入Zotero为存储型子附件；这两份用于本地归档和Zotero阅读管理，不在各章节重复复制原文。

## 2. Zotero 顶层集合

仓库已提供幂等创建脚本：`literature/91-引用与导出/create-zotero-collections.js`。在 Zotero 中进入“工具 → 开发者 → 运行 JavaScript”，粘贴脚本全文并运行，即可在“我的文库”下创建以下集合：

```text
大论文-双轴桨叶式混合机智能设计
├─ 00 待整理
├─ 01 绪论
├─ 02 混合过程与性能分析
├─ 03 性能模型构建与验证
├─ 04 参数寻优与综合评价
├─ 05 智能设计系统开发与验证
├─ 06 总结与展望
└─ 90 跨章节方法与标准
```

各级子集合严格按照 `literature/目录树.md` 创建。摘要、参考文献和致谢不单独建立集合，因为摘要不能引入正文没有的证据，参考文献由 Zotero 全库生成，致谢不需要研究文献。

脚本只创建缺失集合，不会删除、移动或重命名现有集合；重复运行不会重复创建正常的同名层级。运行结果会返回 `createdCount`、`existingCount` 和重名警告。

## 3. 条目字段约定

每篇入库文献至少完成以下处理：

1. 核验题名、作者、年份、来源、卷期页和 DOI/学位授予单位。
2. 在 Zotero 的“其他（Extra）”字段加入：

   ```text
   LIT-ID: LIT-0001
   Thesis-Primary: 1.2.1
   Thesis-Secondary: 2.2.1; 3.2.1
   Thesis-Card: literature/01-绪论/.../LIT-0001_文献简称.md
   ```

3. 将条目加入一个主要章节集合；需要跨章节使用时，可同时加入其他集合，不复制条目和附件。
4. 文献卡片中的 `zotero_item_key` 用于记录 Zotero 条目标识；如果尚未取得该值可暂时留空。

`LIT-ID` 与 Zotero 引用键不是同一概念。`LIT-ID` 用于本论文证据追踪，必须稳定；引用键服务 BibTeX，可能因导出工具或命名规则改变。

## 4. 标签体系

标签不重复表达章节编号，章节归属由集合管理。建议只使用以下三类标签：

### 阅读状态

- `状态/待读`
- `状态/粗读`
- `状态/精读`
- `状态/已摘录`
- `状态/已用于正文`
- `状态/不采用`

### 证据作用

- `证据/背景`
- `证据/定义`
- `证据/机理`
- `证据/方法`
- `证据/公式`
- `证据/参数`
- `证据/比较`
- `证据/局限`
- `证据/验证`

### 来源与对象

- `来源/期刊论文`
- `来源/学位论文`
- `来源/标准`
- `来源/官方文档`
- `对象/双轴桨叶式混合机`
- `对象/相近装备`
- `对象/仅结构参考`

标签必须从上述词表选择，避免出现“已读、读过、精读完成”等同义标签。

## 5. Zotero 批注与仓库摘录的衔接

在 Zotero 阅读器中高亮后，批注备注建议使用统一开头：

```text
[EX-0001][拟用于1.2.1][作用=研究现状][状态=候选]
```

只有准备进入论文的关键批注才转写到 Markdown 文献卡片。转写时必须保留：

- `EX` 编号；
- PDF 页码或图表号；
- 最短必要原文；
- 自己的准确转述；
- 拟使用小节与段落位置；
- 研究对象和适用边界。

Zotero 高亮不等于可以直接粘贴进论文。没有页码、没有边界说明或只是二手转述的批注，不得标记为“可用”。

## 6. 引用库导出

当前本机未检测到 Better BibTeX，因此采用人工导出：

1. 在 Zotero 中选中顶层集合“`大论文-双轴桨叶式混合机智能设计`”。
2. 使用“导出分类/Export Collection”。
3. 需要通用交换时选择 RIS；需要 BibTeX 时选择 BibTeX。
4. BibTeX 导出到 `literature/91-引用与导出/references.bib`。
5. RIS 导出到 `literature/91-引用与导出/references.ris`。
6. 每次覆盖导出后，核对 Zotero 条目数、导出条目数和 DOI 去重结果。

如果以后安装 Better BibTeX，可再设置自动导出；在安装和测试之前，不得把 `references.bib` 当成自动同步文件。

## 7. 日常工作流

### 附件关联是强制入库步骤

2026-09-17用户明确要求：本批及后续论文原文均需关联Zotero，不能仅建文献条目。每次下载后必须执行：

1. 验证PDF等真实格式、题名与作者、非零页数，保存到本地大纲对应目录；不把书目来源当原文。
2. 按DOI或题名和作者在Zotero查重，复用已有文献父条目，加入主要章节集合。
3. 将原文复制导入为该条目的子附件，保留本地源文件；已有同一原文附件则复用，不重复导入。
4. 回读父条目键、附件键、实际文件路径及父子关系；核对PDF可以读取、复制件SHA256与源文件一致。
5. 在卡片的`zotero_attachment`中填写附件键，并更新总表与批次记录；注明实际核查时间。本地关联与云端同步分开，不操作云端时不宣称已同步。

如无法取得合法全文或导入受阻，保留元数据并标记“附件待补”及原因，不能标记入库闭环完成。本规则适用于后续在本仓库处理的文献，不表示所有既有文献已补齐附件。

本批可复用脚本为`91-引用与导出/import-zotero-attachments.js`，读取`zotero-attachments-batch.json`清单。在Zotero官方Run JavaScript中勾选异步执行后运行；只给明确匹配的已有条目添加附件，不直接修改SQLite、不创建重复父条目、不移动源文件、不主动触发云端同步。后续批次需先更新清单并核验文件；生成审计结果后仍须校验SHA256，不以脚本生成代替实际导入验证。

```text
检索/下载
  → 核验元数据和原文格式并查重
  → 本地按大纲归档，复制原文到Zotero对应父条目为子附件
  → 回读父子关系、文件路径和内容一致性
  → 分配 LIT-ID
  → 加入主要章节集合及必要的交叉集合
  → 在 Zotero 中阅读和批注
  → 将关键摘录转写到仓库文献卡片
  → 更新章节文献地图
  → 写入论文正文并插入 Zotero 引文
  → 定稿前复核全文、页码和参考文献表
```
